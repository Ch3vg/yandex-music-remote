# Архитектура YM Remote

Поведение пульта, тексты ошибок, HTTP и WebSocket заданы в `application.md`. Этот файл фиксирует только решения, которых там нет: слои, очередь окна и то, как команда находит трек.

## Слои

Один процесс uvicorn. Точка входа — `ym_remote.interfaces.asgi:app`, не монолит `server_cdp.py`.

- `models` ни от кого не зависит. Объекты неизменяемые, коллекции — кортежи.
- `schemas` — проводной JSON. Двойной `track_id` живёт только здесь: в снимке это строка `артист|название`, в команде воспроизведения — числовой id Яндекса.
- `services` решают политику и не импортируют FastAPI. `TransportService` сам выбирает порядок: страница плейлиста, при неудаче страница трека. На это время опрос ждёт.
- `cdp` кликает по окну. Наследники `CdpAdapter` не открывают своё соединение: в конструктор передаётся общий `CdpSession`.
- `yandex` ходит в API каталога и не занимает очередь окна.
- `interfaces` вызывают сервисы и отдают схемы. Сами по окну не кликают.
- Собранный пульт, если он есть, читается из `web/dist`. Сервер фронтенд не собирает.

## Очередь на одно окно

Очередь одна, в `cdp/session.py`. Воркер выполняет одну транзакцию за раз. Транзакция — весь публичный метод адаптера команды, а не отдельный `Runtime.evaluate`. Пока метод листает плейлист, чужая громкость не вставляет клик между шагами. Два `play_now` встают друг за другом.

Короткий жест тоже идёт через воркер, поэтому не разрезает чужую транзакцию. Между собой короткие жесты просто стоят в очереди.

Опрос в эту очередь не встаёт. `services/gate.py` поднимает флаг на время тяжёлой команды и `GET /search`. Пока флаг поднят, оба цикла монитора пропускают ход и спят: короткий 0,4 с, цикл смены трека 0,5 с. Снимки не копятся пачкой в конце длинной команды.

Вызовы `Runtime.evaluate` дополнительно сериализованы замком сеанса: сокет отладчика один. Пока идёт транзакция, замок держится на всё её тело.

`error`, `notice` и тик после команды уходят только сокету, который команду послал. `now_playing` уходит всем. Периодический `player_tick`, `cdp_status` и `stopped` тоже рассылаются всем, как в контракте.

Запросы библиотеки к API Яндекса в очередь CDP не входят.

## Окно не принадлежит клиенту

Десктопное окно одно на все телефоны. Сервер не помнит страницу сокета. Выдача поиска и список плейлиста живут в ответе HTTP и на телефоне.

Любое действие с конкретным треком внутри своей транзакции заново открывает цель по полям команды:

- Есть `playlist_uuid`: открыть `playlists?playlistUuid=`, найти строку по `trackId`. Индекс нужен только чтобы прокрутить список. `play_now` жмёт Play. `play`, `play_next` и `queue` жмут «следующим». `add_to_queue` жмёт «в конец». Не вышло — страница трека, до трёх раз с паузой 0,8 с.
- Нет `playlist_uuid`: сразу страница `album/track` по `track_id` и `album_id`. Ссылку с этим id в уже открытом документе не ищем: там может быть выдача другого телефона. Меню после успеха делает `history.back()`.
- `play_queue_track` заново открывает панель очереди и жмёт Play у строки с присланным `trackId`.
- Жесты бара смотрят только текущий бар.

Если `album_id` не передан, его добирает каталог как id первого альбома. Если альбома нет и страница трека нужна, пульту уходит текст про отсутствие альбома.

`play_now` с плейлистом и запасной страницей трека — это две транзакции подряд. Флаг тяжёлой команды держится на обе, поэтому опрос между ними не читает окно. Короткая команда другого телефона может встать между этими двумя транзакциями; внутри каждой шаги не перемешиваются.

## Каталог, сеть, картинки

Каталог — библиотека `yandex-music`, токен `YANDEX_MUSIC_TOKEN`. Поиск к API не обращается: его выполняет окно.

Адрес выбирает `net/addresses.py`: отбрасываются `127.*`, `169.254.*` и `172.16.0.0/12`, приоритет `192.168.*`, затем `10.*`. `LOCAL_IP` побеждает, даже если его не было среди обнаруженных, и тогда добавляется в начало `all`. Чужой `ip` у `/qr` заменяется выбранным.

QR запрашивается как version 1, коррекция M, box 10, рамка 4. Короткий URL в version 1 не помещается, поэтому при переполнении берётся следующая версия с теми же коррекцией, размером клетки и рамкой. Иначе код нельзя было бы показать.

Слушаем `0.0.0.0` без аутентификации. Порт по умолчанию 8001, CDP 9222.

## Запуск

Разработка, из корня репозитория, с `PYTHONPATH=src` и `PYTHONUTF8=1`:

```text
.venv\Scripts\python.exe -m uvicorn ym_remote.interfaces.asgi:app --host 0.0.0.0 --port 8001
```

Без токена процесс не стартует и печатает `YANDEX_MUSIC_TOKEN не найден в .env`.

`launcher/start-ym-remote.ps1` находит exe Яндекс Музыки, при необходимости перезапускает его с флагами CDP, поднимает uvicorn в Job Object с `KILL_ON_JOB_CLOSE` и показывает окно QR 360×580. Закрытие окна останавливает uvicorn и не закрывает Яндекс Музыку. Сборка в `YandexMusicRemote.exe` — `launcher/package.ps1`, если установлен ps2exe.

`cdp/restart-server.bat` поднимает тот же uvicorn без окна и ждёт `/network-info`.
