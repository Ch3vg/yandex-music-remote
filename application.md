# YM Remote (CDP)

Пульт Яндекс Музыки. Телефон в локальной сети управляет десктопным приложением на Windows.

Один компьютер с установленной Яндекс Музыкой. Приложение поднимает десктопный клиент с Chrome DevTools Protocol на порту 9222, HTTP-сервер пульта на `0.0.0.0:8001` и окно с QR. Мобильный браузер получает библиотеку, поиск, плеер, очередь и громкость.

Управление плеером идёт через DOM десктопного приложения (`data-test-id`). Каталог «Мне нравится» и плейлисты читаются официальным API по токену. Поиск выполняется в окне десктопного приложения.

Секреты лежат в `.env` в корне проекта: обязательный `YANDEX_MUSIC_TOKEN`, необязательные `LOCAL_IP`, `PORT`, `CDP_PORT`.

Режимы `server.py` и `mirror/` к этому приложению не относятся.

## Процессы

| Процесс | Кто запускает | Жизненный цикл |
|---|---|---|
| Яндекс Музыка | лаунчер | Остаётся после закрытия окна QR |
| uvicorn `server_cdp:app` | лаунчер | Завершается вместе с окном QR |
| Окно QR (WinForms) | лаунчер | Пока открыто, сервер жив |

Пользовательский запуск: `YandexMusicRemote.exe` (сборка `start-ym-remote.ps1` через ps2exe, без консоли, STA, иконка `app.ico`) или `start-ym-remote.vbs` / `cdp/start-cdp.bat`. Оба вызывают корневой `start-ym-remote.ps1`.

Разработческий запуск без окна: `cdp/restart-server.bat`. Скрипт завершает процессы, в командной строке которых есть `server_cdp:app`, очищает `cdp/server-cdp.log` и `cdp/server-cdp.err.log`, стартует uvicorn скрыто и до 15 секунд ждёт `GET http://127.0.0.1:8001/network-info` со статусом 200.

Отдельный запуск только музыки: `cdp/launch-ym-debug.bat`.

Поиск exe, по порядку:

1. `%LOCALAPPDATA%\Programs\YandexMusic\Яндекс Музыка.exe`
2. `%LOCALAPPDATA%\Programs\YandexMusic\YandexMusic.exe`
3. Первый `*.exe` в этой папке, имя которого не содержит `Uninstall` и `Update`.

CDP считается готовым, если на `127.0.0.1:9222` есть TCP и в командной строке процесса есть и `remote-debugging-port`, и `remote-allow-origins`. Иначе все процессы этого exe завершаются (`taskkill /T /F`, до 6 с на выход) и процесс стартует с аргументами `--remote-debugging-port=9222` и `--remote-allow-origins=*`. Ожидание порта — до 20 с. Неудача показывает модальное окно с текстом ошибки.

Сервер пульта: `.venv\Scripts\python.exe -u -m uvicorn server_cdp:app --host 0.0.0.0 --port 8001`, рабочая папка `cdp/`, `PYTHONPATH` указывает на `cdp`, `PYTHONUTF8=1`, `PORT=8001`. Процесс помещается в Job Object с `KILL_ON_JOB_CLOSE`. Готовность проверяется до 20 с по `/network-info`. Закрытие окна и любой выход из скрипта останавливают uvicorn. Яндекс Музыку при этом не закрывают.

Окно QR: 360×580, фиксированное, по центру, фон `#121212`, заголовок «Yandex Music Remote» цветом `#F0C000`. Подпись: «Яндекс Музыка и пульт запущены.» Если процесс музыки перезапускали: «Яндекс Музыка перезапущена с отладкой CDP.» Картинка 220×220 берётся с `GET /qr`, URL показан моноширинным шрифтом. Кнопки: скопировать ссылку, открыть лог в Блокноте, открыть URL в браузере, «Остановить пульт» (закрывает окно).

Каталог `certs/` этот сервер не использует. Пульт отдаётся по HTTP.

При отсутствии токена процесс сервера не стартует и сообщает: `YANDEX_MUSIC_TOKEN не найден в .env`. При старте сервер печатает выбранный URL, прочие адреса и порт CDP.

## Сеть и адреса

Кандидаты собираются через `gethostbyname_ex` и UDP-сокет до `8.8.8.8:80` (нужен локальный адрес сокета). Отбрасываются `127.*`, `169.254.*` и `172.16.0.0/12`. Приоритет: `192.168.*`, затем `10.*`, затем остальные. Если задан `LOCAL_IP`, выбранным считается он, даже когда его нет среди обнаруженных. Иначе берётся первый по приоритету, а при пустом списке — `127.0.0.1`.

Публичный URL: `http://{chosen}:{port}/`. Параметр `ip` у `/qr` принимается, только если адрес есть среди кандидатов или равен `LOCAL_IP`. Иной IP подменяется выбранным.

`GET /network-info`:

```json
{
  "chosen": "192.168.1.10",
  "port": 8001,
  "all": ["192.168.1.10"],
  "url": "http://192.168.1.10:8001/"
}
```

`chosen` стоит первым в `all`. `LOCAL_IP`, которого не было среди обнаруженных, добавляется в начало до этой перестановки.

Порт по умолчанию — 8001. Переменная `PORT` его меняет. `CDP_PORT` по умолчанию 9222.

## WebSocket `/ws`

Клиент шлёт JSON с полем `command`. Сервер шлёт JSON с полем `type`.

При подключении, если снимок плеера уже есть, сервер сразу отправляет `now_playing`. Соединений может быть несколько. Снимок и признак доступности CDP рассылаются всем. Сокет с ошибкой отправки удаляется из списка.

Команды `play_now`, `play`, `play_next`, `queue`, `add_to_queue`, `show_queue`, `refresh_queue`, `play_queue_track` выполняются строго по одной. Пока такая команда выполняется, опрос плеера ждёт. Остальные команды опрос не останавливают и друг друга не блокируют. Сами вызовы CDP по сокету отладчика идут по одному: следующий `Runtime.evaluate` начинается после завершения предыдущего.

### Снимок плеера

Поля добавляются и к `now_playing`, и к `player_tick`:

| Поле | Смысл |
|---|---|
| `track_id` | Строка `"{artist}\|{title}"`. Ключ смены трека в интерфейсе пульта, не числовой идентификатор Яндекса |
| `title`, `artist` | Текст из бара. Повторы имён артистов убираются, имена соединяются через запятую |
| `is_playing` | В баре видна кнопка паузы |
| `cover_url` | Адрес картинки как в DOM |
| `cover_url_hq` | В URL хвост вида `/ШиринаxВысота` заменён на `/1000x1000` |
| `volume` | Целое 0–100 или `null` |
| `artist_href`, `album_href` | Ссылки из бара или `null` |
| `position_sec`, `duration_sec` | Секунды слайдера или `null` |
| `repeat_mode` | `off`, `queue` или `one` |
| `shuffle` | Логическое значение |
| `liked` | Логическое значение |
| `queue_name` | Название контекста воспроизведения |

`now_playing` уходит всем, когда меняется кортеж `(track_id, is_playing, volume, cover_url, repeat_mode, shuffle)`. Позиция в кортеж не входит. `player_tick` уходит всем каждые 0,4 с, пока CDP возвращает трек. Оба сообщения несут полный снимок.

Отдельный цикл с периодом 2 с читает тот же снимок. Если три таких чтения подряд не вернули трек, всем уходит `cdp_status` с `available: false`, сохранённый снимок сбрасывается, и если трек раньше был, уходит `stopped`. Первое успешное чтение после этого рассылает `cdp_status` с `available: true`. Пульт сообщения `cdp_status` не обрабатывает. Точка на главной показывает только состояние сокета пульта: открыт он или нет.

`stopped` прячет мини-плеер.

Пока выполняется тяжёлая команда, оба цикла опроса пропускают ход и ждут: короткий цикл 0,4 с, цикл смены трека 0,5 с.

### Команды клиента

`play_pause`, `next`, `prev` приходят без дополнительных полей. После выполнения сервер через 50, 120 и 120 мс соответственно шлёт этому же сокету `player_tick`.

`prev` на десктопе сначала ставит слайдер таймкода в 0, ждёт 120 мс и один раз нажимает «предыдущая». Текущий трек из-за этого не начинается заново: происходит переход к предыдущему.

`set_volume` принимает `{ "value": число }`. Значение обрезается в диапазон 0–100. Неудача даёт `error` с текстом «Не удалось изменить громкость». Успех — `player_tick` через 60 мс.

`seek` принимает `{ "position_sec": целое }`. Снизу значение обрезается нулём, сверху — максимумом слайдера. Неудача — «Не удалось перемотать трек». Успех — tick через 60 мс.

`set_shuffle` принимает `{ "on": bool }`. Кнопка нажимается, только если текущее состояние отличается от запрошенного. Неудача — «Не удалось переключить перемешивание». Успех — tick через 50 мс.

`cycle_repeat` делает один клик по видимой кнопке повтора. Неудача — «Кнопка повтора не найдена в приложении». Успех — tick через 80 мс.

`set_repeat` принимает `{ "mode": "off" | "queue" | "one" }`. Другое значение молча игнорируется. Сервер нажимает кнопку, пока её `data-test-id` не станет целевым:

- `off` — `REPEAT_BUTTON_NO_REPEAT`
- `queue` — `REPEAT_BUTTON_REPEAT_CONTEXT`
- `one` — `REPEAT_BUTTON_REPEAT_ONE`

Порядок состояний именно такой. Делается до 3 шагов с паузой 90 мс и до 12 проверок по 50 мс. Неудача — «Не удалось переключить повтор». Успех — tick через 50 мс. Пульт этой командой не пользуется: кнопка повтора шлёт `cycle_repeat`.

`track_reaction` принимает `{ "kind": "like" | "dislike" }`. Другой `kind` заканчивается неуспехом без сообщения клиенту. Кнопка ищется в полноэкранном плеере, затем в обычном баре, затем в баре «Моей волны», затем по всему документу. Неудача — «Лайк недоступен — откройте полноэкранный плеер на ПК». Успех — tick через 100 мс.

`navigate` принимает `{ "target": "artist" | "album" }`. Другое значение игнорируется. Выполняется клик по ссылке артиста или обложки в десктопном баре. Неудача — «Не удалось открыть карточку в приложении». Отдельный tick после этой команды не шлётся.

`play_now`:

```json
{
  "track_id": 123,
  "album_id": 456,
  "title": "",
  "artist": "",
  "playlist_kind": 3,
  "playlist_uid": 1,
  "playlist_uuid": "uuid",
  "playlist_track_index": 0
}
```

`track_id` здесь числовой идентификатор Яндекса. Если передан `playlist_uuid`, сначала открывается страница этого плейлиста и нажимается Play на строке. `playlist_track_index` — позиция трека в списке плейлиста с нуля. Если страница плейлиста не включила трек, используется страница трека. Страница трека пробуется до трёх раз с паузой 0,8 с, таймаут одной попытки 35 с. Успех — `player_tick` через 200 мс только этому сокету. Ошибка — `error` только этому сокету.

Команды `play`, `play_next` и `queue` выполняют одно и то же действие: поставить трек следующим, без немедленной смены текущего. `add_to_queue` ставит трек в конец очереди. Набор полей тот же, поля плейлиста необязательны. Успех отвечает `notice` только этому сокету. Текст: `Трек {artist} — {title} — играть следующим` либо `Трек {artist} — {title} — в конец очереди`. Пустые артист и название в середину строки не вставляются. Префикс тогда выглядит как `Трек  — играть следующим`.

`show_queue` и `refresh_queue` отвечают одному сокету:

```json
{
  "type": "queue",
  "before": [],
  "current": null,
  "after": [],
  "before_title": "Предыдущая очередь",
  "after_title": "Далее в очереди",
  "now_meta": { "subtitle": "", "source": "" }
}
```

Элемент очереди содержит `title`, `artist`, `cover`, `track_id` (число или `null`), `album_id`, `is_playing`. У `current` дополнительно `is_current: true`. Чтение очереди открывает боковую панель очереди в десктопном приложении, если она закрыта, и оставляет её открытой. Если панель открыть нельзя, приходит тот же объект с пустыми списками и `current: null`.

`play_queue_track` принимает `track_id` и необязательный `album_id`. Нажимается Play в строке очереди с этим `trackId`. В ответ уходит обновлённый `queue` или `error`.

Неизвестная команда молча игнорируется.

Сообщения `error` и `notice` имеют вид `{ "type": "error"|"notice", "message": "текст" }`.

## Каталог через API

Используется библиотека `yandex-music`, асинхронный клиент, токен из окружения. Обложка API: при отсутствии схемы добавляется `https://`, подстрока `%%` заменяется на `200x200`. Поле `cover_url_hq` получает замену хвоста размера на `/1000x1000`.

Трек каталога:

```json
{
  "id": 1,
  "album_id": 2,
  "title": "",
  "artist": "A, B",
  "cover_url": "",
  "cover_url_hq": ""
}
```

`album_id` берётся из альбомов трека. Если альбомов нет, берётся `album_id` позиции плейлиста. Артисты склеиваются через запятую.

Карточка плейлиста содержит `kind`, `uid`, `playlist_uuid`, `title`, `track_count`, `cover_url`, `is_likes`. Карточка считается «Мне нравится», если заголовок равен `Мне нравится` или `kind` равен 3.

`GET /api/library/home`:

```json
{
  "likes": {
    "title": "Мне нравится",
    "tracks": [],
    "kind": 3,
    "uid": 1,
    "playlist_uuid": null,
    "track_count": 0,
    "cover_url": null
  },
  "playlists": []
}
```

`tracks` — не больше 12 первых лайков, в порядке `users_likes_tracks`. `playlists` — плейлисты пользователя с непустым названием, без карточки «Мне нравится». Счётчик, uid, uuid и обложка лайков уточняются отдельным запросом плейлиста с найденным `kind`. Если такого плейлиста в списке нет, `kind` остаётся 3, `uid` — идентификатор аккаунта.

`GET /api/library/playlist/{kind}` возвращает плейлист текущего пользователя: `kind`, `uid`, `playlist_uuid`, `title`, `tracks`. Треки идут в порядке плейлиста. Пустой результат API даёт ошибку «Плейлист не найден».

Поиск к API не обращается.

Если `album_id` не передан в команду воспроизведения, он запрашивается у API как идентификатор первого альбома трека.

## Управление десктопным приложением

Список страниц CDP запрашивается по `GET http://127.0.0.1:{CDP_PORT}/json` без прокси, таймаут 2 с. Берутся объекты с `type` равным `page`. Счёт страницы: +1000, если URL содержит `music-application`; +200, если URL содержит `album/track` или `/track`; −800, если URL содержит `user-id` или `passport`. Выбирается страница с наибольшим счётом, у неё берётся `webSocketDebuggerUrl`. Соединение одно и пересоздаётся при смене URL или ошибке сокета. Перед работой отправляется `Runtime.enable`. Выражение выполняется методом `Runtime.evaluate` с `returnByValue: true` и `awaitPromise: true`. Сообщения с другим `id` пропускаются. Исключение JavaScript и результат с subtype `error` считаются неуспехом. Таймаут по умолчанию 3 с. У поиска, меню трека и страницы трека таймаут 25–35 с, у чтения очереди 8 с, у установки повтора 8 с, у клика из очереди 15 с.

Значение полей ввода задаётся через нативный setter прототипа `HTMLInputElement` или `HTMLTextAreaElement`, затем отправляются события `input` и `change` с `bubbles: true`.

Элемент считается видимым, если он в документе, его ширина и высота не меньше 2 px, а вычисленные `display` и `visibility` не равны `none` и `hidden`.

Корни плеера, по порядку: элемент `FULLSCREEN_PLAYER_MODAL`, элемент `PLAYERBAR_DESKTOP`, элемент `VIBE_PLAYERBAR`, затем `document.body`.

Имена ниже — значения атрибута `data-test-id`, если не сказано иное.

Очередь. Панель — `PLAY_QUEUE`. Кнопка открытия — `PLAYERBAR_DESKTOP_PLAY_QUEUE_BUTTON`. Если у панели нулевая ширина или высота, кнопка нажимается и выдерживается пауза 350 мс. Блоки: `PLAY_QUEUE_BEFORE_PLAYING_BLOCK`, `PLAY_QUEUE_NOW_PLAYING_BLOCK`, `PLAY_QUEUE_AFTER_PLAYING_BLOCK`. Строка трека — `TRACK_PLAYLIST` или `TRACK_ALBUM`. Ссылка `a[href*="trackId="]` разбирается как URL, из неё берутся `trackId` и `albumId`. Обложка строки — `ENTITY_COVER_IMAGE`. Название — `TRACK_TITLE`. Артисты — `SEPARATED_ARTIST_TITLE`. Строка считается играющей, если внутри есть `PAUSE_BUTTON`. Подзаголовок и источник текущего блока — `PLAY_QUEUE_NOW_PLAYING_BLOCK_SUBTITLE` и `PLAY_QUEUE_NOW_PLAYING_BLOCK_TITLE`. Заголовок блока «далее» — `PLAY_QUEUE_AFTER_PLAYING_BLOCK_TITLE`, а если его нет, на пульте используется «Далее в очереди». Заголовок предыдущего блока на пульте всегда «Предыдущая очередь».

Клик по строке очереди: панель при необходимости открывается с ожиданием 500 мс. Если в строке уже есть `PAUSE_BUTTON`, трек считается уже играющим. Иначе строка прокручивается к центру и нажимается `PLAY_BUTTON`. Результат `playing` или `already` — успех. Иначе ошибка «Не удалось включить трек из очереди».

Поиск меняет страницу десктопного окна. Сначала закрывается видимая панель очереди повторным нажатием её кнопки, с паузой 250 мс. Затем нажимается `NAVBAR_NAVIGATION_ITEM_SEARCH`, пауза 700 мс, ожидается корень `SEARCH_PAGE`. Поле ввода ищется так: `SEARCH_PAGE_SEARCH_INPUT input`, сам `SEARCH_PAGE_SEARCH_INPUT`, `SEARCH_INPUT input`, `SEARCH_INPUT`, затем `input` с placeholder, содержащим «чувствуете» или «оиск». Текст задаётся native setter, затем события `input`, `change`, `keydown` и `keyup` с клавишей Enter. Строки результатов — `SEARCH_TRACK_CARD`. До 25 раз с паузой 300 мс ожидается смена сигнатуры: склейка названий первых 8 строк. В ответ попадают не больше 15 строк, у которых есть непустой title и числовой trackId. Артист собирается из `SEPARATED_ARTIST_TITLE`, `.artist` и `a[href*="/artist"]`. Если их нет, берётся `aria-label` строки. Обложка — `ENTITY_COVER_IMAGE`. Для каждой обложки считается `cover_url_hq`.

Включение со страницы трека. При протоколе страницы `music-application:` адрес равен `music-application://desktop/album/track?albumId={album}&trackId={id}`. Без album параметр `albumId` опускается. При другом протоколе используется относительный `/album/track?...`. Ожидание — до 60 шагов по 250 мс. На шагах 4 и 12 переход повторяется, если страница ещё не та. Успех: href содержит нужный `trackId` и, когда album задан, нужный `albumId`; в баре есть ссылка с этим `trackId`; в баре видна кнопка паузы. Главная кнопка Play берётся со страницы `TRACK_PAGE` и не берётся из блока `TRACK_PAGE_SIMILAR_TRACKS` и не из строки `TRACK_PLAYLIST`, `TRACK_ALBUM` или `SEARCH_TRACK`. Области поиска кнопки по порядку: `TRACK_PAGE_CONTENT`, `ENTITY_HEADER`, `BASE_PAGE_HEADER_CONTROLS`, `BLOCK_HEADER`. Внутри области предпочтение у видимой `PLAY_BUTTON_WITH_COVER` и её внутреннего `PLAY_BUTTON`, затем у видимого `PLAY_BUTTON`, затем у кнопки, чей `aria-label` содержит «Воспроизведение» или «Слушать». Видимость здесь требует ширину и высоту больше 8 px. Коды успеха сценария — `playing` и `started`.

Включение и меню со страницы плейлиста. Если href ещё не содержит и `playlistUuid`, и конкретный uuid, выполняется переход на `music-application://desktop/playlists?playlistUuid={uuid}` или на `/playlists?playlistUuid={uuid}`. Готовность проверяется до 24 раз каждые 120 мс после начальной паузы 450 мс. Строка ищется по ссылке с `trackId` внутри `PLAYLIST_PAGE`, иначе внутри `main`, иначе по документу. Если задан album и в ссылке есть `albumId`, он должен совпасть. Контейнер прокрутки — ближайший предок элемента `TRACK_PLAYLIST` с `overflow-y` равным `auto`, `scroll` или `overlay` и с `scrollHeight` больше видимой высоты более чем на 4 px. Иначе сам scope, если он прокручивается, иначе документ.

Пока строка не найдена, первый шаг прокрутки ставит `scrollTop` в 0. Если известен индекс, затем выставляется позиция примерно `(index - 2) * (высота первой строки + 2)`. Следующие шаги прокручивают последнюю видимую строку к концу и добавляют 72% высоты контейнера, но не меньше 280 px. Число шагов хранится в `sessionStorage` под ключом, зависящим от id трека и действия (`play`, `next` или `end`), и перед попыткой сбрасывается. Между шагами пауза около 220–280 мс. Всего до 120 шагов. Шесть ответов «конец списка» подряд прекращают попытку. Для Play успех — коды `playing` и `started`. Для пункта меню успех — `ok`. Отсутствие кнопки Play, пункта «следующим» или пункта «в очередь» — немедленный отказ.

Play на строке плейлиста: строка прокручивается к центру, нажимается видимый `PLAY_BUTTON` или кнопка с aria-label «Слушать» / «Воспроизведение». До 6 раз по 120 мс проверяется, что бар уже показывает этот `trackId` и паузу.

Меню строки: на строку отправляются `mouseenter` и `mouseover`. Затем ищется первая из кнопок `TRACK_CONTEXT_MENU_BUTTON`, `TRACK_PLAYLIST_CONTEXT_MENU_BUTTON`, `CONTEXT_MENU_BUTTON`. Иначе кнопка, чей `aria-label` в нижнем регистре содержит «ещё», «опци» или «меню». Если кнопки нет, по ссылке трека отправляется `contextmenu`. После открытия меню пауза 480–580 мс. Пункт «следующим»: `TRACK_CONTEXT_MENU_PLAY_NEXT_BUTTON` или `TRACK_CONTEXT_MENU_PLAY_NEXT`. Пункт «в конец»: `TRACK_CONTEXT_MENU_ADD_TO_QUEUE`, `TRACK_CONTEXT_MENU_ADD_TO_QUEUE_BUTTON`, `TRACK_CONTEXT_MENU_QUEUE`, а если их нет — любой `data-test-id`, содержащий `ADD_TO_QUEUE`. После клика пауза 250 мс и клавиша Escape. Если пункта нет, тоже отправляется Escape.

Запасной путь, когда uuid плейлиста нет. Ищется любая ссылка с нужным `trackId`. Если её нет, создаётся и нажимается временная ссылка `/album/track?albumId={album}&trackId={id}` (без album параметр опускается), затем до 25 раз по 200 мс ссылка ищется снова. Меню открывается кнопкой `TRACK_CONTEXT_MENU_BUTTON` или `TRACK_HEADER_CONTEXT_MENU_BUTTON` в строке `SEARCH_TRACK_CARD`, `TRACK_PLAYLIST`, `TRACK_ALBUM`, `SEARCH_TRACK` или на странице `TRACK_PAGE`. Если ради действия выполнялся переход на страницу трека, после успеха вызывается `history.back()`.

## Пульт

Один HTML-документ, язык `ru`. Viewport: ширина устройства, `user-scalable=no`, `viewport-fit=cover`. Цвет темы `#000000`. Включены `apple-mobile-web-app-capable` и `mobile-web-app-capable`, заголовок приложения «YM Remote», стиль статус-бара iOS `black-translucent`. Подключены manifest и `apple-touch-icon`.

Колонка контента не шире 480 px и центрируется. Шрифт: `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `Roboto`, без засечек. Цвета: фон `#000000`, поверхности `#1c1c1e` и `#2c2c2e`, текст белый, приглушённый белый 55% и 35%, акцент `#ffcc00`, разделитель белый 8%. Высота мини-плеера 64 px, таббара 52 px, снизу добавляется `env(safe-area-inset-bottom)`. Нажатие на кнопку снижает непрозрачность до 0,7. Подсветка тапа отключена.

Экраны: `home`, `playlist`, `search`, `player`, `volume`, `more`. Среди обычных экранов активен один. Плеер лежит поверх и появляется анимацией 320 мс. Класс `player-open` на `body` скрывает мини-плеер. Класс `chrome-hidden` скрывает таббар. Класс `mini-absent` убирает нижний отступ под мини-плеер. Отступы контента пересчитываются из этих классов, чтобы список не прятался под панелями.

Таббар виден на поиске, если на него перешли кнопкой таба, а также на экранах громкости и «Ещё». Таббар скрыт на главной, на плейлисте, на плеере и на поиске, открытом кнопкой с главной. Подсвечивается только таб поиска, громкости или «Ещё», и только когда активен соответствующий экран. Подписей у табов три: «Поиск», «Громкость», «Ещё». У каждой есть иконка. Отдельной вкладки «Главная» нет.

Точка статуса есть в шапке главной. При открытом сокете у неё класс `online`, подсказка «Подключено». После закрытия сокета класс снимается, подсказка «Переподключение…», новое соединение начинается через 2 с. На экране громкости есть вторая точка без логики.

### Главная

Шапка: слева кнопка QR, справа точка статуса и кнопка поиска.

Герой «Мне нравится»: обложка 88×88, радиус 12. Пока обложки нет или она не загрузилась, показан градиент от `#ff6b4a` через `#e91e3a` к `#c4145c` и значок сердца. Заголовок берётся из API, запасной текст «Мне нравится», справа шеврон. Под ним счётчик. Склонение: 1 трек, 2–4 трека, 5–0 и числа 11–14 — треков. Тысячи разделяются неразрывным пробелом. Нулевой счётчик скрывается. Тап по герою открывает полный плейлист лайков (`kind` из ответа, иначе 3).

Карусель предпросмотра: первые 12 треков, по три в карточке. Горизонтальная прокрутка со snap, у правого края виден следующий фрагмент шириной около 28 px, зазор 8 px. Полоса прокрутки скрыта. Тап по строке включает трек сейчас. Кнопка из трёх точек открывает лист действий и не включает трек. Пустой список заменяется текстом «Нет треков». На время загрузки показывается «Загрузка…».

`playlist_index`, который уходит вместе с треком из карусели, — это позиция трека среди этих 12 записей, а не позиция в полном плейлисте лайков.

Ниже сетка остальных плейлистов. Карточка: обложка, название, строка «{track_count} треков» при ненулевом счётчике. Тап открывает экран плейлиста. Пустой список — «Нет плейлистов». Ошибка запроса показывается и в карусели, и в сетке, счётчик героя становится «—».

Пока активна главная, контекст команд треков — `playlist_kind`, `playlist_uid` и `playlist_uuid` лайков. Контекст задаётся только когда uuid лайков непустой.

### Плейлист

Кнопка назад возвращает на главную. Заголовок сначала равен названию с карточки, после ответа API заменяется на `title` из ответа. Поле с placeholder «Поиск в плейлисте» фильтрует уже загруженный массив по вхождению строки в склейку названия и артиста, без нового запроса. Регистр не учитывается. Список: обложка, название, артист, кнопка меню. Тап по строке включает трек сейчас. Пока идёт запрос, виден текст «Загрузка…». Пустой результат фильтра — «Ничего не найдено». Ошибка запроса показывается текстом `detail` или «Не удалось загрузить плейлист».

Контекст команд на этом экране: `playlist_kind` равен kind, с которым открыли экран, `playlist_uid` и `playlist_uuid` берутся из ответа. `playlist_track_index` — позиция трека в полном загруженном массиве, поиск по числовому `id`. Индекс отфильтрованного вида не используется.

### Поиск

Кнопка поиска на главной открывает экран без таббара. Кнопка назад снимает этот режим и возвращает на главную. Таб «Поиск» открывает тот же экран с таббаром и без кнопки назад; заголовок по центру — «Поиск».

Поле: placeholder «Трек, альбом, исполнитель», `autocomplete=off`, `enterkeyhint=search`. Enter запускает поиск. Отдельной кнопки запуска нет. Пустой запрос ничего не делает. На время запроса список показывает «Ищем в приложении…». Ответ — массив треков. Пустой массив — «Ничего не найдено». Ошибка HTTP показывает `detail` или «Ошибка поиска». Строка устроена так же, как в плейлисте: тап включает сейчас, три точки открывают лист.

Пока открыт поиск, контекст плейлиста пуст. Команда уходит без `playlist_uuid`, и десктоп включает трек через страницу трека. Сам поисковый запрос при этом открывает поиск в окне Яндекс Музыки на ПК.

### Лист действий

Нижняя панель. Закрывается кнопкой «Отмена» и тапом по затемнённому фону. В шапке название и артист. Пункты:

- «Включить сейчас» отправляет `play_now`
- «Играть следующим» отправляет `play_next`
- «Добавить в очередь» отправляет `add_to_queue`

Поля команды: числовой `track_id`, числовой `album_id` или `null`, `title`, `artist`. Если на текущем экране есть контекст, добавляются `playlist_uuid`, `playlist_kind`, `playlist_uid`. Если у трека есть неотрицательный `playlist_index`, добавляется `playlist_track_index`.

### Мини-плеер

Скрыт, пока не пришёл снимок, и скрыт, пока открыт полный плеер. После `stopped` снова скрыт. Тап по строке открывает полный плеер. Тап по кнопке play/pause плеер не открывает. Слева обложка, название и артист, справа кнопка play/pause. Подложка строится из обложки. Прогресс — ширина левого слоя поверх подложки, в пикселях от ширины панели и доли позиции.

Горизонтальный жест показывает три панели: предыдущий трек, текущий, следующий. Предыдущий — последний элемент `before`. Следующий — первый элемент `after`. Если соседа нет, панель пустая, смещение пальца умножается на 0,22 и жест не фиксируется. Порог фиксации — меньшее из 88 px и 28% ширины. При фиксации лента доезжает на ширину панели за 0,32 с с кривой `cubic-bezier(0.32, 0.72, 0, 1)` и отправляется `prev` или `next`. В следующие 450 мс тап по мини-плееру полный плеер не открывает. Жест не начинается на `button`, `input`, ссылке и элементе с атрибутом `data-no-swipe`. Направление выбирается после сдвига больше 6 px по одной из осей. Вертикальное движение жест отменяет.

Соседи запрашиваются командой `refresh_queue` при открытии сокета и ещё раз через 280 мс после смены `track_id`. Смена трека возвращает ленту в центральное положение.

### Полный плеер

Открывается поверх текущего экрана. Закрытие запоминает последний обычный экран и возвращает на него. Экраны громкости и плеер в это запоминание не пишутся. Поиск, открытый с главной без таббара, тоже не затирает запомненную главную.

Шапка: кнопка свернуть, по центру название очереди, справа кнопка очереди. Пустое название показывается как «—».

Свайп вниз по фону плеера сворачивает его, если вертикальное смещение больше 56 px и больше горизонтального в 1,2 раза. Пока идёт горизонтальный свайп треков, вертикальный жест не обрабатывается. Горизонтальный свайп устроен так же, как у мини-плеера, боковые панели показывают крупную обложку, название и артиста.

Ниже таймлайна и подписей времени стоит строка: маленькая обложка, название, артист. Тап по этой строке отправляет `navigate` с `target: artist`.

Таймлайн — `input type=range` от 0 до длительности в секундах. Подписи в формате `m:ss` без часов. Пока воспроизведение идёт, позиция на пульте досчитывается каждые 200 мс: к последней серверной секунде прибавляется прошедшее локальное время, но не дальше длительности. Во время перетаскивания серверные тики ползунок не перезаписывают. Событие `input` обновляет только левую подпись. Событие `change` отправляет `seek` с целым значением ползунка. Пока `duration_sec` в снимке не больше нуля, длительность на пульте сохраняется прежней, а `position_sec` обновляет опорную точку. Изменение размера мини-плеера перерисовывает прогресс.

Ряд кнопок слева направо: «не нравится», перемешивание, предыдущий трек, play/pause, следующий трек, повтор, «нравится». Под рядом — ползунок громкости и динамическая иконка.

Перемешивание сразу переключает класс активности и шлёт `set_shuffle` с новым значением. Лайк сразу меняет вид и шлёт `track_reaction` с `kind: like`. У кнопки лайка два сердца: контур и заливка. Активное состояние ставит `aria-pressed=true` и подпись «Убрать из коллекции», неактивное — «Нравится». Дизлайк вид заранее не меняет и шлёт `track_reaction` с `kind: dislike`.

Повтор сразу показывает следующее состояние цикла `off`, затем `queue`, затем `one`, затем снова `off`, и отправляет `cycle_repeat` без поля mode. Неактивная кнопка — режим `off`. Активная — `queue`. Активная с дополнительным классом `repeat-one` — режим `one`. Следующий снимок с сервера выставляет вид по полю `repeat_mode`.

Play/pause сразу меняет иконки и локальный флаг воспроизведения, затем отправляет `play_pause`. Подпись кнопки — «Пауза» или «Воспроизведение». На полном плеере и на мини-плеере иконки совпадают. До первого снимка показана иконка play.

Громкость — целое 0–100. Ползунок в плеере и ползунок на экране «Громкость» показывают одно значение. Пока значение только что пришло из снимка, обработчик `input` команду не отправляет. Каждое пользовательское движение ползунка отправляет `set_volume`. Иконка — три дуги: первая приглушена только при 0, вторая видна с 35, третья с 70. При нуле поверх рисуется крест. На экране громкости иконка 56 px и рядом текст `{значение}%`. В плеере иконка 22 px. Начальное значение до первого снимка — 50.

Обложка красит фон плеера и мини-плеер. Картинка грузится с `crossOrigin` равным `anonymous` и рисуется на canvas 56×56. Пиксели с альфой меньше 100 пропускаются. Для цветного среднего пропускаются пиксели, у которых максимум канала меньше 42 или разница максимума и минимума меньше 20. Если цветных пикселей меньше 10, берётся среднее по всем непрозрачным. Из среднего цвета считаются верх и низ фона плеера и цвета свечения мини-плеера. Если цвет признан нейтральным, фон плеера ставится в `rgb(42, 44, 50)` и `rgb(28, 30, 36)`. Ошибка загрузки или отсутствие canvas оставляет нейтральную тёмную подложку. Повторный приход того же URL обложку заново не считает. Нет обложки — подложка сбрасывается, на месте картинки знак ♪.

Название контекста в шапке обновляется из `queue_name` снимка и из `now_meta.source` или `now_meta.subtitle`, когда приходит очередь.

### Очередь на пульте

Лист на весь экран. Открытие отправляет `show_queue` и, пока лист открыт, каждые 2,5 с отправляет `refresh_queue`. Закрытие листа останавливает этот интервал. Кнопка закрытия — «назад» в шапке листа. Сворачивание плеера лист тоже закрывает.

Секции рисуются только если в них есть данные. Заголовок предыдущих треков — `before_title`. Заголовок текущего — `now_meta.subtitle` или «Сейчас играет»; если есть `now_meta.source`, к заголовку добавляется ` · ` и этот текст. Заголовок следующих — `after_title`. У текущего трека к названию добавляется префикс `▶ `. Тап по строке, у которой `track_id` не пустой, отправляет `play_queue_track` с `track_id`, `album_id`, `title` и `artist`.

Если все три части пусты, одна строка: «Очередь пуста или панель не открылась в приложении».

Первое открытие прокручивает список так, чтобы якорь оказался у верхнего края с отступом 6 px. Якорь — элемент предыдущего блока, стоящий за три позиции до конца `before`. Если предыдущих треков меньше или их нет, якорь — текущий трек. Если якоря нет, запасная цель — строка с классом текущего, и отступ равен 22% высоты области прокрутки. Повторные обновления, пока лист открыт, сохраняют `scrollTop`.

Пока лист закрыт, сообщение `queue` всё равно обновляет соседей для свайпа. Если в `now_meta` есть source или subtitle, обновляется и заголовок плеера.

### Тосты и QR

Тост ошибки и тост notice висят 5 секунд и добавляются в общий контейнер. Класс тоста разный.

Лист QR с главной и раскрывающийся блок «QR для подключения» на экране «Ещё» запрашивают `/network-info`. Картинка: `/qr?ip={chosen}&t={текущее время в мс}`. Под ней URL, кнопка «Скопировать ссылку» и абзац: «Отсканируйте QR или скопируйте ссылку и откройте в браузере телефона. На некоторых Android после скана доступно только «Копировать».» Успешное копирование даёт notice «Ссылка скопирована», неудача — «Не удалось скопировать». Лист QR закрывается кнопкой «Закрыть» и тапом по фону. На экране «Ещё» под блоком QR есть текст: «Пульт управляет Яндекс Музыкой на компьютере через CDP.»

Обложки в списках: если в адресе нет схемы `http` или `https`, добавляется `https://`. Подстрока `%%` заменяется на `200x200`. Если картинка не загрузилась, на её месте остаётся пустой квадрат.

При загрузке страницы открывается главная, запрашивается `/api/library/home` и открывается WebSocket на том же хосте: `ws:` или `wss:` в зависимости от схемы страницы, путь `/ws`. Service worker регистрируется по `/sw.js`. Ошибка регистрации нигде не показывается.

## Зависимости

Python-пакеты сервера: `fastapi`, `uvicorn[standard]`, `python-dotenv`, `yandex-music[ynison]`, `aiohttp`, `pillow`, `qrcode[pil]`, `websocket-client`. Пакеты `pynput` и `pygetwindow` в CDP-пульте не вызываются.

## Наблюдаемые сценарии

1. Музыки нет или она запущена без CDP. Лаунчер завершает её процессы, запускает с портом 9222, дожидается `/network-info` и показывает QR. Подпись говорит, что музыка перезапущена с отладкой CDP. Телефон открывает URL, точка становится «Подключено», главная показывает лайки и плейлисты.
2. Музыка уже слушает порт 9222 и в её командной строке есть оба флага отладки. Лаунчер её не завершает. Подпись: «Яндекс Музыка и пульт запущены.»
3. Exe Яндекс Музыки в `%LOCALAPPDATA%\Programs\YandexMusic` нет. Появляется сообщение, что приложение не найдено. Сервер пульта не стартует.
4. Нет `.venv\Scripts\python.exe`. Появляется сообщение с путём к интерпретатору. Сервер не стартует.
5. В баре играет трек. Мини-плеер показывает название, артиста и обложку. Подпись времени и полоска прогресса двигаются каждые 200 мс между тиками сервера. Пауза останавливает этот локальный ход.
6. Свайп мини-плеера и полного плеера меняет трек, когда с соответствующей стороны есть элемент очереди. У края списка палец сдвигает ленту примерно на пятую часть и она возвращается.
7. Свайп вниз и кнопка свернуть возвращают на экран, с которого плеер открыли. С экрана громкости и с экрана «Ещё» это главная или плейлист, если плеер открывали оттуда, а не сам экран громкости.
8. Тап по треку на главной или в плейлисте отправляет `play_now` с uuid плейлиста. Десктоп открывает страницу этого плейлиста и нажимает Play на строке. Если это не удаётся, открывается страница трека.
9. Тап по результату поиска отправляет `play_now` без uuid. Десктоп к этому моменту уже находится на странице поиска, потому что сам запрос открыл её в приложении.
10. «Играть следующим» показывает notice и не меняет текущий трек сразу. «Добавить в очередь» показывает другой notice, со словами «в конец очереди».
11. Открытая очередь на пульте повторяет три блока панели на ПК. Текущий трек помечен префиксом. Тап по строке с числовым id включает её. Закрытие листа останавливает опрос каждые 2,5 с. Панель очереди на ПК после чтения остаётся открытой.
12. Ползунок громкости, перемотка, перемешивание и повтор после ближайшего тика показывают то состояние, которое прочитано из десктопного приложения.
13. Лайк меняет сердце сразу, затем снимок подтверждает или возвращает прежний вид. Если кнопки лайка в приложении нет, появляется тост про полноэкранный плеер.
14. Кнопка «назад» уводит на предыдущий трек и тогда, когда текущий уже играет больше нескольких секунд: перед кликом таймкод обнуляется.
15. Несколько открытых пультов получают один и тот же `now_playing`. Ошибка команды приходит только на сокет, который команду отправил.
16. Три неудачных чтения снимка с интервалом 2 с прячут мини-плеер сообщением `stopped`. Следующий успешный снимок показывает его снова.
17. Запрос `/qr` с адресом, которого нет среди локальных и который не равен `LOCAL_IP`, кодирует выбранный адрес машины, а не переданный.
18. Закрытие окна QR останавливает uvicorn и не закрывает Яндекс Музыку.
19. `cdp/restart-server.bat` поднимает пульт без окна. `http://127.0.0.1:8001/` отвечает страницей пульта.
